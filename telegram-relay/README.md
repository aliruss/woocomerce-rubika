# WooCommerce Telegram Relay Server

This is the Phase 2 relay server for **WooCommerce Rubika Bridge**. The WordPress plugin sends product payloads to this service; the relay validates the request, downloads product images, sends the post to Telegram Bot API, cleans up temporary files, and returns a structured JSON response.

The relay exists so WordPress does **not** need to store or call the Telegram bot token directly.

## Requirements

- Python 3.10+
- A Telegram bot token from BotFather
- A Telegram chat/channel where the bot can post
- HTTPS reverse proxy in production (Nginx/Apache/Caddy recommended)

## Installation

```bash
cd telegram-relay
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env
```

## Environment configuration

All secrets are loaded from `.env`. Never commit real `.env` files.

| Variable | Required | Description |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | yes | Telegram Bot API token from BotFather. |
| `TELEGRAM_CHAT_ID` | yes | Target chat/channel ID, e.g. `@channel_username` or `-100...`. |
| `RELAY_API_KEY` | yes | Shared API key. Must match WordPress Telegram Relay API Key. |
| `RELAY_HMAC_SECRET` | no | If set, relay requires `X-Relay-Signature` HMAC SHA256 over raw body. |
| `ALLOWED_ORIGINS` | no | Comma-separated allowed origins, e.g. `https://example.com`. Empty disables origin check. |
| `MAX_IMAGE_SIZE_MB` | no | Maximum image download size. Default: `10`. |
| `LOG_LEVEL` | no | `DEBUG`, `INFO`, `WARNING`, or `ERROR`. Default: `INFO`. |
| `TEMP_DIR` | no | Temporary image download directory. Default: system temp. |
| `PORT` | no | Port used by `python app.py`. Default: `8000`. |

## Running in production

Recommended pattern:

1. Run Uvicorn on `127.0.0.1:8000` using systemd.
2. Put Nginx/Apache/Caddy in front with HTTPS.
3. Configure the WordPress plugin Telegram Relay URL to `https://your-domain.example/send/telegram`.

Example systemd unit is included at `examples/telegram-relay.service`.

```bash
sudo mkdir -p /opt/telegram-relay
sudo cp -r telegram-relay/* /opt/telegram-relay/
cd /opt/telegram-relay
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
sudo cp examples/telegram-relay.service /etc/systemd/system/telegram-relay.service
sudo systemctl daemon-reload
sudo systemctl enable --now telegram-relay
```

## API endpoint

### `POST /send/telegram`

Headers:

- `Content-Type: application/json`
- `X-Relay-Api-Key: <RELAY_API_KEY>`
- `X-Relay-Signature: <hex-hmac-sha256>` when `RELAY_HMAC_SECRET` is configured

Example payload accepted from the WordPress plugin:

```json
{
  "network": "telegram",
  "request_id": "telegram-123-uuid",
  "product": {
    "id": 123,
    "title": "Product title",
    "url": "https://example.com/product/product-title",
    "price": "100,000 تومان",
    "short_description": "Product short description",
    "social_text": "Final selected social text",
    "caption": "Final caption generated by WordPress",
    "images": [
      {
        "id": 11,
        "url": "https://example.com/wp-content/uploads/product-image-1.jpg",
        "mime": "image/jpeg"
      }
    ]
  },
  "options": {
    "image_count": 2,
    "parse_mode": "HTML",
    "send_as_album": true
  }
}
```

Structured success response:

```json
{
  "success": true,
  "request_id": "telegram-123-uuid",
  "product_id": 123,
  "network": "telegram",
  "method": "sendPhoto",
  "telegram_message_id": 456,
  "response_summary": {
    "message_ids": [456],
    "valid_images": 1
  }
}
```

## Example curl request

```bash
curl -X POST https://relay.example.com/send/telegram \
  -H 'Content-Type: application/json' \
  -H 'X-Relay-Api-Key: replace-with-a-long-random-secret' \
  --data @payload.json
```

If HMAC is enabled, calculate the signature over the exact raw JSON body and pass it as `X-Relay-Signature`.

## Telegram sending behavior

- One valid image: uses `sendPhoto` with product caption.
- Two to ten valid images: uses `sendMediaGroup`; caption is attached to the first media item.
- More than ten images: only first ten are used (Telegram media group limit).
- No valid images: falls back to `sendMessage` and response/logs clearly indicate no valid image was available.
- Long text: caption is shortened to Telegram's caption limit while preserving the product link; full text is sent as additional message chunks.
- Parse mode: HTML is preferred. User text is escaped before sending as HTML to avoid malformed Telegram HTML.

## Image download and cleanup

For each image URL, the relay:

1. Downloads with timeout.
2. Validates HTTP status.
3. Validates image content type.
4. Enforces `MAX_IMAGE_SIZE_MB`.
5. Writes to a temp file.
6. Sends to Telegram.
7. Deletes temp files in `finally`, including failures.

## Logs and troubleshooting

Logs include safe context:

- `request_id`
- `network`
- `product_id`
- image download/validation status
- Telegram method used
- cleanup status

Logs never include:

- `TELEGRAM_BOT_TOKEN`
- `RELAY_API_KEY`
- `RELAY_HMAC_SECRET`
- full auth headers

Common issues:

- `401 Missing API key`: WordPress did not send `X-Relay-Api-Key`.
- `403 Invalid API key`: WordPress key does not match `.env`.
- `401 Missing HMAC signature`: `RELAY_HMAC_SECRET` is set but WordPress did not sign.
- `502 Telegram API failure`: bot token/chat permissions are wrong or Telegram rejected the payload.
- `No valid image was available`: image URLs were blocked, too large, unsupported, or returned non-200.

## Testing Telegram connection

1. Start the relay.
2. Open `/health`.
3. Use the WordPress plugin **Test Telegram relay** button.
4. Send a product using **شبکه اجتماعی → ارسال به تلگرام**.
5. Check system logs (`journalctl -u telegram-relay -f`) and WordPress logs.

## Security notes

- Keep the relay behind HTTPS.
- Use a long random `RELAY_API_KEY`.
- Enable `RELAY_HMAC_SECRET` for stronger request integrity.
- Restrict `ALLOWED_ORIGINS` to your WordPress domain when practical.
- Do not expose this service publicly without API key/HMAC.
- Do not log secrets.

## Manual message payloads (v1.5.0)

The relay also accepts WordPress manual social messages using `type=manual` without a WooCommerce product object:

```json
{
  "network": "telegram",
  "request_id": "manual-uuid",
  "type": "manual",
  "message": {
    "text": "Line 1\n\nLine 2",
    "images": [
      {"id": 11, "url": "https://example.com/wp-content/uploads/manual.jpg", "mime": "image/jpeg"}
    ]
  },
  "options": {
    "image_count": 1,
    "parse_mode": "HTML",
    "send_as_album": true
  }
}
```

Manual text line breaks are preserved. Product payload support remains unchanged.
